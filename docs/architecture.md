# Архитектура

## Разделение ответственности

Проект — статическое приложение с нативными JavaScript ES-модулями и SVG-холстом. Локальный HTTP-сервер обслуживает файлы; базовые сценарии не требуют серверной базы данных или внешнего AI-сервиса.

Данные проходят три независимых этапа:

1. Запрос преобразуется в набор разрешённых идентификаторов предметов.
2. Раскладка определяет позиции, роли и повороты с общим масштабом сцены.
3. Рендерер загружает соответствующие исходные SVG, применяет палитру и собирает отображение/экспорт.

Такое разделение позволяет проверять смысловой подбор отдельно от SVG и заменять интерпретатор без изменения редактора.

## Библиотека

Каталог хранит семантический идентификатор, русское название, синонимы, теги и четыре исходных варианта: L/main, L/background, S/main, S/background.

У варианта есть путь к файлу и исходные размеры. Происхождение связано с node ID оригинальной группы Figma. Контрольные суммы позволяют обнаружить изменение извлечённого файла. Они подтверждают стабильность сохранённых байтов, но сами по себе не доказывают визуальное совпадение с Figma.

Файлы предметов сохраняются отдельно от пользовательских композиций. При добавлении объекта в сцену не создаётся новое изображение и не изменяется исходный файл.

## Модель сцены

Базовая модель:

```json
{
  "width": 1200,
  "height": 630,
  "detail": "L",
  "paletteId": "исходная-схема",
  "backgroundIndex": 0,
  "scale": 0.5,
  "objects": [
    {
      "id": "уникальный-экземпляр",
      "assetId": "book",
      "x": 600,
      "y": 315,
      "rotation": 0,
      "role": "main"
    }
  ]
}
```

Координаты задают центр экземпляра. Порядок объектов определяет порядок наложения. Один общий коэффициент масштаба сохраняет относительные размеры предметов. При S/L используется соответствующая исходная геометрия с нормализацией базового масштаба библиотеки.

Импортированная палитра может храниться в данных сцены как `customPalette`; тогда она имеет приоритет при разрешении выбранной схемы.

## Цветовые роли

Исходные оттенки сопоставляются ролям: фоновые оттенки, объектные акценты, контуры и нейтральные цвета. Замена палитры применяется к заливкам и контурам, не меняя векторные координаты.

Цвет фона выбирается только из фонового набора. Объектам разрешены фоновые оттенки и объектные акценты. Главный/фоновый статус использует соответствующий исходный SVG, а не случайное обесцвечивание.

## Экспорт

Экспорт включает размер и viewBox сцены, фон и отдельные предметные группы. Перемещение, поворот и общий масштаб выражаются преобразованиями групп.

Каждому экземпляру требуется собственное пространство внутренних ID. Ссылки `url(#...)` и `href="#..."` должны указывать на переименованные определения того же экземпляра. Это особенно важно при дублировании объектов с масками или градиентами.

Итог должен быть самостоятельным SVG без временных Figma URL, bitmap-вложений и зависимостей от страницы редактора. Расширение .svg само по себе недостаточно: проверяются структура и повторный импорт.

## Автосборка

Сценарий названий учитывает нормализацию, синонимы, формы слов и несколько предметов в строке. Неизвестные элементы не следует незаметно заменять.

Сценарий метафор использует конечный локальный словарь тем и связей. Подбор объясняется пользователю; низкая уверенность и отсутствие совпадений обозначаются явно. Словарь не является универсальной языковой моделью.

Раскладка использует воспроизводимые шаблоны для широкого, квадратного и вертикального холста. Seed позволяет менять композицию без случайной генерации графики.

## Внешняя модель: необязательное расширение

Для произвольных формулировок можно добавить серверный адаптер: запрос + краткий каталог → структурированный список разрешённых assetId и ролей. Ответ необходимо валидировать по схеме и белому списку. SVG и координаты контуров модель не создаёт.

API-ключ при таком расширении должен храниться на сервере. Текущая автономная версия не требует ключа и не заявляет подключение внешней модели.

## Хранение и границы

Исходники и палитры — статические данные проекта. Состояние редактора живёт в браузере. Публикация исходников и передача иллюстраций не меняют прав правообладателя.

Фактические результаты автоматических и ручных проверок вынесены в отдельный отчёт QA; этот документ описывает устройство решения и не подменяет протокол проверки.
